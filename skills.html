Reference

Skills

Skills are model-agnostic playbooks that teach a coding agent how to use Notchlet correctly: which commands to run, which state to read first, what evidence to record, and what never to do without authorization.

What a skill is

A skill is a directory containing a SKILL.md with YAML frontmatter (name, description) and a short operating guide. Clients that support skills load the matching guide when a request routes to it; clients invoke them by slash command or natural language.

  • Skills are guidance, not a runtime. They call the CLI and MCP tools that actually exist.
  • They are written to be resumed: read current state, reuse the workspace and change, and avoid replaying setup or planning.
  • They preserve authorization boundaries and evidence rules rather than optimizing for a “done” message.

Install and update

The CLI installs generated guidance into the client's skill directory:

notchlet client init opencode --apply     # .opencode/skills
notchlet client init claude --apply       # .claude/skills
notchlet client init agent --apply        # .agents/skills

notchlet client update opencode --apply   # refresh without touching MCP config
notchlet client update claude --apply
TargetDirectoryAvailable through
opencode.opencode/skillsclient, init --client, mcp configure
claude.claude/skillsclient, init --client, mcp configure
agent.agents/skillsclient only

notchlet init --client opencode|claude installs skills and configures the local MCP server in one step for offline work. Use notchlet client update to refresh guidance without rewriting MCP configuration.

Two installation paths

The Notchlet skills repository can also be installed with the general skills tooling (for example npx skills add against the repository). CLI-installed guidance is generated and syntax-checked against the CLI release; repository installs track the latest committed skills.

Intent routing

notchlet-super routes from the request and the current workspace state:

IntentAction
Explore or investigateRead source, tests, docs, or bounded MCP context. No init, writes, transitions, sync, or checkpoints unless asked.
Plan onlyUse notchlet-plan; do not implement or deliver. A local change plan can be refined without starting tasks.
Continue or resumenotchlet status and instructions --action resume; continue eligible tasks without recreating the plan.
Revise requirements or designinstructions --action revise; preserve stable IDs and progress, then revalidate.
Implement or verifyUse notchlet-implement plus the repository's real test commands.
ReviewUse notchlet-review; distinguish self-recorded checks from independent review.
DeliverUse notchlet-deliver; evaluate readiness, then update state only as authorized.

Invoking skills

Clients that expose skills usually accept a slash command matching the skill name. Others route from the description:

/notchlet-super implement NOT-123

# or, conversationally:
Use the notchlet workflow to implement the search endpoint.
Resume the change I started yesterday; do not re-plan it.
Review the open PR against its acceptance criteria.

A good request names the outcome and, when known, the backlog key or change name. “Continue” is sufficient when state already exists — the router reads it instead of asking you to re-explain.

Generated guidance

CLI-bundled guidance is generated from the skills repository:

  1. Read the source skills

    The generator reads every SKILL.md from the skills project.

  2. Validate the command surface

    Documented CLI commands are checked against the CLI implementation so guidance does not advertise commands that do not exist.

  3. Emit client variants

    Outputs are written per client (opencode, claude-code, agent) with a manifest and compatibility metadata.

  4. Test and bundle

    Tests regenerate and compare outputs. Releases bundle the generated guidance, so installed clients receive it with the CLI.

Release lag

Bundled guidance reflects the CLI release it shipped with. If the skills repository has newer fixes than your installed CLI, use notchlet client update after upgrading, or install from the repository. Check versions with notchlet --version.

Writing a skill

  • Start with frontmatter: a short name and a description that states exactly when the skill applies.
  • Write an operating guide, not an essay: entry criteria, ordered actions, commands, and a checklist.
  • Name real commands and flags. The generator rejects guidance that references commands the CLI does not ship.
  • Include failure handling: pre-existing failures, missing credentials, and authorization limits.
  • Never include tokens, credentials, or customer data; describe environment-variable references instead.
  • Keep it resumable: tell the agent to read current state before recreating plans or setup.

Example: agent request, end to end

# In OpenCode with skills installed
Use the notchlet workflow to add CSV export to the reports page.
The backlog item is NOT-142.

# Router behavior:
# 1. notchlet-super reads workspace and item state
# 2. notchlet-platform resolves the product and bounded context
# 3. notchlet-plan confirms acceptance criteria and creates a local change
# 4. notchlet-implement starts tasks, implements, and verifies with evidence
# 5. notchlet-review checks the diff and tests
# 6. notchlet-deliver records evidence and updates status once authorized
